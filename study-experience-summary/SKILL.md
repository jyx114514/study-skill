# 学习与经验总结（Study & Experience Summary）

## Overview

将用户提供的 **AI 对话聊天记录** 整理为结构清晰、便于理解、可长期保存和查阅的**知识文档**。

**输出格式（重要）：默认输出 Markdown（.md）文件**；只有当用户明确要求 HTML / 网页版（如"要html"、"转成网页"、"生成网页版"）时才输出独立 HTML 文件。不要主动输出 HTML，除非用户提出。

这不是聊天记录的流水账摘要，而是把聊天过程中获得的知识、经验和最终解决方案重新组织成一份**以后真正可以学习、复习和复用的个人知识文档**——即使几个月后忘记这次聊天，只读这份文档也能快速重新理解知识，或重新完成当时的问题解决过程。

**核心执行原则：**

> 完整阅读对话 → 识别主题 → 判断属于学习知识、技术排错或混合内容 → 提取真正有价值的信息 → 合并零散追问 → 压缩无意义试错 → 按知识逻辑重新组织 → 必要时绘制图表（MD 用 Mermaid，HTML 用 SVG）→ 生成 Markdown（默认）→ 保存到项目文件夹。

## Workflow

### Step 1 — 完整阅读对话并识别主题

- 通读整段聊天记录（不要只看开头几条消息）。
- 判断内容属于哪一类：
  1. **学习与知识类** — 名词/概念/机制解释、代谢通路、信号通路、分子机制、生物化学/细胞生物学知识、数学/统计/计算机/深度学习知识、公式/算法/模型原理、概念比较；
  2. **技术与问题解决类** — 软件安装配置、模型部署、编程调试、环境配置、报错排查、参数调整、试错过程、最终方案、可复用命令/代码/配置；
  3. **混合内容** — 同时包含以上两者，按各自原则分节处理。
- 识别记录中出现的**全部主题**，判断哪些属于同一知识体系（应整合），哪些彼此独立（可拆分为多个文档）。

### Step 2 — 判断整理结构

- **学习类** → 用知识逻辑结构（见 Step 4），目标是"帮助理解和复习"。
- **技术排错类** → 用"问题→原因→解决→复现"结构（见 Step 5），目标是"以后能复现解决过程"。
- **混合类** → 先知识后技术，或按主题块各自采用合适结构。

### Step 3 — 合并追问与压缩试错

- **合并追问**：围绕同一知识点的多轮追问（"什么是 A？""A 和 B 有何区别？""为什么 A 导致 C？""D 有什么作用？""A 和 E 什么关系？"）必须识别为同一知识体系，重新组织为连续结构（A 定义 → A 与 B 区别 → A 如何影响 C → D 的作用 → A 与 E 的关系），**不要**做成五段独立问答。
- **压缩试错**：重复尝试/失败方案/排查过程**不要逐条记录**。压缩为一句话说明（"排查过程中尝试了多种方案，但均未解决问题，最终确认问题由 XXX 导致"），然后重点解释 XXX 是什么、为什么导致问题、如何确认、最终改了什么、正确操作是什么、如何验证已解决。除非某个失败方案本身具有重要警示价值，否则不详细记录。

### Step 4 — 学习类内容组织

按知识本身的逻辑灵活组织，可用结构（**不要求机械使用全部章节**）：

1. 核心概念
2. 基本定义
3. 组成部分
4. 工作机制 / 生物学机制
5. 过程或通路
6. 上游与下游关系
7. 关键分子 / 蛋白 / 酶 / 参数
8. 调控机制
9. 生物学意义或实际作用
10. 与相似概念的区别
11. 容易混淆的地方
12. 核心知识总结

**通路/机制/流程类知识**（代谢通路、信号通路、合成过程、分子机制、神经通路、算法流程、数据处理流程、模型工作流）必须重点整理 **起点 → 中间步骤 → 关键节点 → 调控关系 → 最终结果**，让读者理解"这个过程为什么会这样发生，各部分之间是什么关系"，**不要只罗列名词**。必要时用箭头、流程图或图表将复杂关系可视化（Markdown 用 Mermaid 代码块；HTML 用 SVG）。

### Step 5 — 技术排错类内容组织

采用：

**问题是什么 → 原因是什么 → 最终如何解决 → 以后如何复现**

需要重点提取并保留：

- 使用的软件、框架或模型；
- 问题表现；
- 关键报错；
- 根本原因；
- 最终解决方案；
- 修改前后的关键差异；
- 可直接复用的命令（代码块展示）；
- 可直接复用的代码（代码块展示）；
- 配置文件中的关键参数；
- 容易再次踩坑的地方。

**路径/用户名/设备名等仅适用于当前电脑的内容应泛化**（写成 `<模型目录>`、`<项目目录>`、`<用户名>`、`<模型文件.gguf>` 等），但**真正影响问题的版本号、参数值、报错内容不要随意泛化**。

### Step 6 — 生成知识文档（默认 Markdown，HTML 仅按需）

**默认输出：Markdown（.md）文件。** 只有当用户明确要求 HTML（说"要html"、"转成网页"、"生成网页版"等）时，才输出独立 HTML 文件。

**Markdown 版要求（默认）：**
- 使用标准 Markdown 语法：标题层级（`#`/`##`/`###`）、列表、表格、代码块（fenced code block，含语言标注）、引用块、加粗/斜体。
- 图表用 Mermaid 代码块（```mermaid，如 mindmap / flowchart / sequenceDiagram / timeline）。
- 对重要概念和结论用加粗/引用突出；代码、命令、报错用代码块区分；注意事项可用引用块或加粗前缀。
- 文件名以 `.md` 结尾，保存到当前项目文件夹。

**HTML 版要求（仅用户明确要求时）：**
- 必须是一个**独立 HTML 文件**，可直接用浏览器打开。
- **不依赖外部 CSS 或 JavaScript**；CSS 直接内嵌在 HTML 中；正确显示中文（`<meta charset="UTF-8">`）；页面结构清晰；适合作为长期学习笔记；合理标题层级；对重要概念和结论突出显示；对代码/命令/报错/注意事项使用明显不同的视觉样式。
- 图表用内嵌 SVG。
- 整体风格：**简洁、专业、知识笔记、技术文档、易于复习**。不要为视觉效果加入大量无实际意义的装饰。
- 可复用 `assets/note-template.html` 作为骨架（含内嵌 CSS 样式体系），在此基础上填充内容。
- 文件名以 `.html` 结尾，保存到当前项目文件夹。

### Step 7 — 图表可视化

当图示能明显提高理解效率时，添加可视化（**以帮助理解为首要目标**，不要为丰富页面强行加图）：
- **Markdown（默认）**：使用 Mermaid 代码块（```mermaid：mindmap / flowchart LR-TD / sequenceDiagram / timeline）。
- **HTML（用户要求时）**：直接内嵌 SVG。

推荐场景：

- **生物学**：代谢通路、信号通路、蛋白质相互作用、上下游调控关系、生物学过程、分子机制、细胞结构关系。
- **计算机/深度学习**：神经网络结构、Attention 机制、数据流、模型架构、算法流程。
- **技术排错**：软件组件关系、请求调用链、Bug 产生机制、修改前后对比、排查流程、文件结构。

重点信息可视化还可使用：流程图、对比表格、时间线、层级结构图、因果关系图、上下游关系图、"修改前 vs 修改后"、"概念 A vs 概念 B"。**尤其对于生物学通路和深度学习模型结构，仅靠文字难以形成整体认识时，优先使用图表。**

### Step 8 — 信息准确性（必须严格遵守）

- 原则上**只根据聊天记录中已有的信息**进行总结。
- **禁止编造**：未验证的原因、未执行过的命令、未确认有效的解决方案、不存在的实验或测试结果、聊天中没有依据的知识结论。
- 技术问题最终未解决 → 明确标记 **「本次对话中尚未得到最终解决。」**
- 技术结论只是推测 → 明确标记 **「可能原因 / 推测」**，不要写成已确认事实。
- 写完后按 Step 9 复核一遍再交付。

### Step 9 — 重点突出（按内容类型）

- **技术排错类**：若最终找到解决方法，设置醒目的 **「最终解决方案」** 区块（即使不读完整排查过程，也能快速知道：最终原因、最终修改、最终命令、最终配置、如何验证已解决）。
- **学习类**：不需要强行设置"最终解决方案"。在文章末尾设置 **「核心知识总结」**：最重要概念、关键机制、关键因果关系、容易混淆点、最值得记忆的内容——作为快速复习入口。

### Step 10 — 文件保存

- 保存到**当前项目的项目文件夹**中，不保存到项目外临时目录。
- **默认输出 `.md` 文件**；用户明确要求 HTML 时输出 `.html` 文件。
- 文件名根据聊天记录的核心内容自动生成（避免 `总结.md` / `result.md` / `output.md` / `1.md` 这类无意义文件名）：
  - `糖酵解与三羧酸循环知识总结.md`
  - `MAPK信号通路机制总结.md`
  - `Attention与KV_Cache原理总结.md`
  - `Ollama_GGUF模型加载错误排查与解决.md`
  - `Qwen模型NextN兼容性问题解决.md`
  - （HTML 版同名替换扩展名为 `.html`）
- 一份记录含多个明显独立大主题 → 可合理拆分多个文档；属于同一知识体系 → 尽量整合为一份完整文档。
- 项目中已存在同主题总结 → **优先更新/扩展已有文档**，避免产生大量高度重复文件。
